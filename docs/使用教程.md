# YouTube Bili Localizer 详细使用教程

本教程面向第一次使用本项目的用户，按 Windows 环境说明完整流程：启动应用、首次配置、处理视频（单条与批量）、术语表、双语字幕样式、字幕精修、视频修改、可选中文配音、发布辅助、文件管理、诊断，以及常见问题排查。本教程对应 0.3.0 版本。

> 请只处理你拥有版权、已获得作者明确授权，或许可证允许下载、改编和转载的视频。本工具不会绕过平台登录、验证码、风控、版权检查或最终发布确认。B 站流程不会自动点击「立即投稿」。

---

## 1. 项目能做什么

一个把授权视频自动处理成**带中文字幕视频**的本地工具，全流程都在图形界面（工作台）中完成：

1. **获取素材**：从 YouTube 授权链接下载，或导入本地视频；
2. **生成源字幕**：`faster-whisper` 转写音频 + OCR 识别画面文字；
3. **合并校对**：音频/画面字幕按时间线合并，可选 DeepSeek/OpenAI 校对；
4. **翻译中文**：生成适合硬字幕的中文翻译；
5. **压制视频**：`ffmpeg` 把字幕压入视频；
6. **字幕精修**：改文字、改时间、删字幕，重新渲染；
7. **视频修改**：删除片段、截取保留、静音、导出片段、片段重排；
8. **发布辅助**：Playwright 打开 B 站创作中心辅助填表（不自动投稿）。

## 2. 启动应用

### 2.1 Windows 便携 ZIP（推荐）

打开项目的 GitHub Releases 页面，找到 v0.3.0，下载 `YouTubeBiliLocalizer-v0.3.0-windows-x64.zip`，将 ZIP 解压到有写入权限的文件夹，再运行解压目录内的 `YouTubeBiliLocalizer.exe`，无需安装。需要安装向导时，可下载同一页面里的 `YouTubeBiliLocalizer-v0.3.0-setup.exe`。

当前公开 Windows 二进制未签名，Windows 仍可能显示 SmartScreen 或其他安全检查。运行前请在发布页核对对应的 SHA-256 校验文件；选择 ZIP 便携版不会取消系统安全检查。

桌面窗口需要 Microsoft WebView2；默认音频流程需要 FFmpeg/ffprobe 和所选 Whisper 模型。首次进入应用后可在「依赖」中心按需安装或下载组件。

### 2.2 源码运行

```powershell
git clone <项目仓库地址>
cd youtube-bili-localizer
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
playwright install chromium
# 另需安装 ffmpeg 并加入 PATH（管理员 PowerShell：winget install Gyan.FFmpeg）
python scripts\launch_workbench.py
```

> 首次启动需要十几秒（加载模型依赖），窗口出现后底部显示「本地服务已就绪」即可使用。

### 2.3 本地构建 EXE（可选）

自行用 PyInstaller 打包后，双击 `dist\YouTubeBiliLocalizer.exe` 即可（需先安装 ffmpeg）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_exe.ps1
```

### 2.4 前置依赖

- 图形版点击顶部「**依赖**」打开依赖中心。FFmpeg 是默认流程必需组件，可一键安装；安装完成后应用会立即重新检测，不必重启或手工配置 PATH；
- **Whisper small 模型**：可在首次处理前预下载，也可由转写流程按需下载；
- **Node.js**（可选但建议）：YouTube 视频流现在需要 JS 挑战求解，依赖中心可安装并自动检测；
- **Tesseract OCR**（可选，仅「画面字幕 OCR」需要）：依赖中心按需安装；
- **投稿辅助浏览器**（可选）：只有使用 B 站登录检查、上传与填表时需要；
- **WebView2**：桌面窗口自身依赖。若系统缺失，启动器会给出明确提示并打开微软官方安装页；
- **NVIDIA GPU**（可选）：有 CUDA 时「推理设备」选 CUDA 可加速转写。

每次安装都会先显示用途与预计占用并要求确认；同一时间只运行一个安装任务。可在依赖中心取消安装，WinGet/投稿浏览器子进程会同步结束；Whisper 会在当前网络请求结束后停止并保留可续传文件。失败时展开安装日志，修复网络或权限问题后点「重试」。缺少 WinGet 时会显示微软 App Installer 说明入口。

## 3. 首次配置（必读）

点击顶部「**设置**」进入设置面板：

### 3.1 配置翻译 API Key（必须，除非用「不翻译」）

1. 打开 https://platform.deepseek.com 注册并创建 API Key；
2. 「设置 → API Key」填入，点「保存本地设置」。

> Key 只写入本机用户目录的 `.env` 文件，不会通过接口回显。

### 3.2 YouTube 自动浏览器验证与 Cookies

v0.2.3 默认开启「YouTube 自动浏览器验证」。当 YouTube 要求媒体请求携带 PO Token 时，应用会按需短暂启动最小化的 Chrome/Edge；验证令牌只服务于当前请求。公开可观看的视频先保持「不使用 Cookies」即可。

Cookies 不是所有下载的必需项，也不能代替 PO Token。只有视频本身要求登录（例如年龄、会员或私有权限）时，才需要使用你自己的登录 Cookies。

Chrome / Edge 130 及以上版本对 Cookies 做了应用绑定加密，**无法直接读取**，只能通过文件方式：

1. Chrome 打开 https://www.youtube.com 并**确认右上角已登录**（头像可见）；
2. 安装扩展 **Get cookies.txt LOCALLY**；
3. 在 YouTube 页面点扩展图标 → **Export**；
4. 把导出文件（通常在「下载」目录，文件名类似 `www.youtube.com_cookies.txt`）通过「设置 → Cookies 文件 → 选择文件」选中并保存；
5. **保存时应用会自动校验**：文件必须包含 `SID` / `LOGIN_INFO`，否则会提示「未登录状态下导出」，需要重新登录再导出。

> 备选方案：在 **Firefox** 中登录 YouTube 后，「设置 → YouTube Cookies 来源」直接选 Firefox。登录状态仍可能过期，并非永久有效。

### 3.3 Cookies 有效期

YouTube 登录态会过期。失败时先看任务检查器给出的错误分类：PO Token 失败先检查 Chrome/Edge 和验证组件；明确要求登录时再更新 cookies.txt；HTTP 429 再等待或更换合规网络出口；一般 403 可能来自令牌、网络或权限，不能只凭状态码判断原因。

## 4. 界面总览

左侧导航有五个工作区：

| 页面 | 用途 |
|---|---|
| **素材** | 粘贴链接 / 导入本地视频、确认授权、读取标题时长 |
| **处理** | 字幕来源、模型、翻译、高级参数、处理结果对照 |
| **字幕** | 预览视频、编辑字幕、样式设置、视频修改 |
| **发布** | 文案模板、B 站投稿辅助 |
| **文件** | 任务历史、输出文件管理、空间清理 |

顶部按钮：**设置**（Key/Cookies）、**检查器**（任务进度与日志）、**开始处理**（创建任务）、**基础/高级模式**切换。

## 5. 素材页

### 5.1 从链接处理

1. 在「视频链接」粘贴完整的 http(s) 链接；
2. 点「**读取标题与时长**」（或在输入框按回车）确认可访问；
3. 按需设置「URL 读取长度」（默认 10 秒，勾选「完整视频」则下载全片）和下载画质（默认 1080p）；
4. 勾选「我确认拥有处理、转载或发布该视频的授权/许可证」；
5. 点「**下载并处理**」。

> 「仅接受 CC reuse allowed」默认不勾选（绝大多数视频没有该标记，勾选会导致无法下载）。只有在你明确需要该限制时才勾选。

> 720p 适合低配置电脑，1080p 是推荐值。选择「原始画质」且素材包含 4K 流时，应用会在开始前警告；4K 会显著增加下载、OCR、渲染与磁盘负载。处理页的「字幕渲染」默认选自动：检测到 NVIDIA NVENC 时优先使用显卡，否则使用 CPU；显卡编码启动失败也会自动降级。

### 5.2 从本地视频处理

1. 勾选授权确认；
2. 点「**选择本地视频**」→ 文件对话框默认打开在输出目录；
3. 选中的视频出现在「已导入视频」列表；
4. 点「**处理本地视频**」。

> 桌面版导入本地视频**直接使用原路径，不会复制**，不占双倍磁盘。

### 5.3 顶部「开始处理」按钮

素材页选择好素材或链接后，顶部「开始处理」即可一键启动；任务运行中按钮变为「中断任务」。

### 5.4 批量处理（0.3.0 新增）

1. 勾选「**批量（每行一个链接，或粘贴播放列表链接）**」；
2. 在输入框里每行粘贴一个链接，或粘贴一个播放列表链接，解析后会列出其中的视频；
3. 勾选要处理的视频。需要配音时可勾选「**同时生成配音版（整批共用）**」；
4. 点「**加入批量并开始**」。

批量处理的规则：

| 项 | 说明 |
|---|---|
| 处理设置 | 沿用当前处理页的设置（翻译器、术语表、字幕样式等） |
| 处理顺序 | 串行，一次只处理一条 |
| 处理范围 | 只处理到压制字幕（以及可选的配音版），**不会自动投稿** |
| 状态 | 每条显示等待中 / 处理中 / 已完成 / 失败 / 已停止 |
| 停止 | 点「**停止批量**」停止整个队列 |
| 续跑 | 失败或已停止的条目点「**续跑**」，从中断的阶段继续，已完成的阶段不重做 |
| 重启恢复 | 关闭程序后重新打开，队列自动恢复 |

> 会员或地区限制的视频可能失败，不影响队列里的其他条目。需要降低画质的条目会停下来标为失败，你确认后再续跑。

## 6. 处理页

### 6.1 基础模式（默认）

- **字幕来源**：自动检测 / 音频+OCR 合并 / 仅音频（推荐）/ 仅画面 OCR；
- **翻译器**：DeepSeek（推荐）/ OpenAI / 不翻译；
- **字幕排版**：中文单语 / 原文在上+中文在下 / 中文在上+原文在下。

其余参数点「**展开全部选项**」或顶部「切到高级模式」查看。

### 6.2 高级模式（18 项参数）

除基础项外还包括：

- **Whisper 模型**：tiny（最快）→ small（推荐）→ large-v3（最准，最慢）；
- **源语言**：留空自动检测；
- **翻译模型**：留空使用默认；
- **目标语言**：默认 zh-Hans；
- **推理设备 / 计算精度**：有 NVIDIA GPU 选 CUDA + float16，否则 CPU + int8；
- **转写束宽 beam_size**：1 快 / 5 推荐 / 10 更准；
- **OCR 帧间隔 / 识别区域 / 最小字符数 / OCR 语言**：默认每 0.5 秒取帧并优先上次成功区域，低置信度时自动扩大搜索；准备检查会验证所选 Tesseract 语言包；
- **字幕底部位置**：3%～15%，控制字幕贴底程度；
- **渲染质量 CRF**：18 高质量 / 20 推荐 / 23 平衡 / 28 小文件；
- **智能上下文翻译**：翻译前让模型先校对源字幕；
- **智能字幕换行排版**：按时长自动断句换行；
- **渲染后打开 B 站创作中心**：任务完成后自动进入发布辅助。

### 6.3 文本处理结果（实时）

任务进入转写阶段（约 48%）后，处理页底部实时显示**逐条对照**：

- 每条字幕带来源徽章：**语音 / 画面文字 / 合并**；
- 转写完成即显示原文；翻译完成后自动更新为中文译文（翻译中显示「翻译中…」）。

### 6.4 术语表（0.3.0 新增）

术语表用来固定人名、车队名、专有名词等的译法。术语会用于所有翻译模式（包括 TranslateGemma 本地翻译）、源文校对和语音识别提示。

- **打开**：点「**术语表 · 编辑**」（按钮上会显示当前条数），打开「编辑术语表」弹窗；
- **编辑**：点「**＋ 新增术语**」添加一行，直接在表格里修改或删除；
- **保存**：点「**保存术语表**」后才生效。原文有重复时不能保存，请先改掉重复的行；
- **关闭**：有未保存的改动时，关闭前会询问「术语表有未保存的改动，确定放弃吗？」；
- **导入 / 导出**：支持 JSON 和 CSV。导入后会提示覆盖了几条、新增了几条，同样要点「保存术语表」才生效；
- **全局与任务**：默认编辑全局术语表；单个任务可以另有一份，优先于全局。

> 改了术语表后，只需重新翻译，已完成的语音识别不会重跑。术语表为空时，效果和 0.2.60 相同。

### 6.5 双语字幕样式（0.3.0 新增）

双语字幕可以选择原文行的显示方式，只影响原文行，译文行和单语字幕不变：

| 选项 | 效果 |
|---|---|
| **弱化原文（小一号、浅灰）**（默认） | 原文行 0.85 倍字号、浅灰色 |
| **小字原文（更小、更灰）** | 原文行 0.7 倍字号、更深的灰色 |
| **两行一致** | 原文和译文同样字号、同样颜色，和 0.2.x 一样 |

改了样式后需要重新渲染才会体现在成片里。

### 6.6 中文配音（可选，0.3.0 新增）

配音需要先自己安装 VoxCPM2，步骤见 `docs/配音安装说明.md`。没装好时配音开关显示为灰色，下方显示原因和安装提示。

1. 在「**配音**」设置中勾选「**生成配音版（*_dub.mp4）**」；
2. 选择混音方式：默认保留背景、压低原声；也可以选「**只留配音**」；
3. 正常开始处理。压完字幕后会多出一个「配音」阶段，另外输出 `*_dub.mp4`，字幕版成片照常保留；
4. 完成后在字幕页预览切到「**配音版**」，或点「**打开配音版**」；
5. 改了字幕后可以点「**重新配音**」。

> **AI 标识与音色**：配音版是 AI 合成的。投稿 B 站时，建议在创作声明里勾选「使用人工智能合成技术」（具体选项以 B 站投稿页当前显示为准）。程序只使用 VoxCPM2 的内置音色，没有声音克隆功能，请不要拿它冒充他人。VoxCPM2 模型卡禁止用它冒充他人、诈骗或造谣，并要求标注 AI 生成；《人工智能生成合成内容标识办法》已于 2025 年 9 月 1 日起施行。参考：[VoxCPM 许可证（Apache-2.0）](https://github.com/OpenBMB/VoxCPM/blob/main/LICENSE)、[VoxCPM2 模型卡](https://huggingface.co/openbmb/VoxCPM2)、[《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)。以上仅供参考，不构成法律意见。

> 配音按字幕时间逐句对齐，一句太长时最多加速到 1.35 倍；配置了 DeepSeek / OpenAI / Ollama 时会先把过长的句子改短再合成，仍然放不下才截断。配音时显存峰值约 5.7 GB。

## 7. 字幕页

### 7.1 预览

- 顶部播放器可切换「原片 / 成片」；
- 时间轴色块 = 每条字幕，点击跳到对应时间；播放时当前字幕自动高亮。

### 7.2 编辑字幕（任务完成后）

- **改文字**：直接在「中文翻译」列编辑；
- **改时间**：时间列两个输入框（格式 `分:秒`，如 `0:05.0`）；
- **自动对齐**：当画面有 OCR 字幕时，点「自动对齐」用画面帧级时间自动校正音频字幕的整体偏移（处理流程中也会自动执行）；无 OCR 时提示无法对齐；
- **整体偏移**：输入 ±秒（如 `0.5` / `-0.5`）一键平移所有字幕时间；
- **删除字幕**：行尾「删除」按钮，该段不再显示字幕（可「恢复」）；
- **撤销 / 重做**：编辑过程中可回退；
- **保存**：写入真实 SRT；未保存时顶部有「未保存修改」提示；
- **重新渲染**：按当前样式和修改后的文字重新压制。

> 开始新任务或切换素材前，若有未保存修改会先弹确认，防止误丢。

### 7.3 字幕样式

- **显示模式**：中文单语 / 双语两种顺序；
- **字体 / 字号 / 字幕颜色 / 边框颜色 / 效果（描边、阴影）**；
- 改完后点「重新渲染」生效（字号按视频分辨率自动缩放，1080p 下推荐值即正常观感）。

### 7.4 视频修改

「视频修改」卡片提供五种操作（修改后字幕时间轴自动对齐并重新压制）：

| 操作 | 用法 |
|---|---|
| **删除片段** | 选时间区间 → 添加 → 「删除选中区间」 |
| **截取保留** | 只保留选中区间，其余删除 |
| **片段静音** | 指定区间静音（画面保留） |
| **导出片段** | 选起止 → 「导出为新文件」，另存不覆盖当前成片 |
| **片段重排** | 分割点（如 `0:10,0:20`）+ 新顺序（如 `3,1,2`）→ 应用重排 |

> 修改会重写当前成片，可连续操作；修改前建议先「保存」字幕。

## 8. 发布页

### 8.1 文案模板

- 选择模板后，「模板内容」可直接编辑（编辑后显示「草稿未保存」）；
- 点「**更新文案**」按**当前草稿内容**生成简介（草稿优先于已保存模板）；
- 「恢复模板内容」还原；「新建/保存为模板」把草稿存为自定义模板；
- 支持变量：`{source}`（原视频链接）、`{custom_text}`（自定义内容）。

### 8.2 B 站投稿辅助

1. 选择「成品来源」（当前任务成片 / 本地选择成片 / 历史输出文件）；
2. 确认标题、简介、标签、追加备注；
3. 点「**登录检查**」确认 B 站登录态；
4. 点「**打开投稿辅助**」→ 自动打开创作中心、选择视频、填写表单；
5. 页面显示实时状态：**正在打开 / 已到人工提交前 / 失败原因**；
6. **人工检查分区、声明、封面、简介后手动点击「立即投稿」**。

> 程序只会把投稿页填到「立即投稿」之前，**最后一步一定要你自己点**。批量处理不会自动投稿，每条视频都要单独走一遍上面的步骤。有配音版时，在「成品来源」里选择对应的 `*_dub.mp4` 即可。投稿配音版时，建议在创作声明里勾选「使用人工智能合成技术」（具体选项以 B 站投稿页当前显示为准）。

- 反馈问题时把这个 zip 发给维护者即可。发出前建议自己打开检查一遍。

## 12. 常见问题（FAQ）

**Q1：YouTube 链接读取或下载失败？**
先保持「自动浏览器验证」开启，并确认依赖中心显示验证组件已包含、Chrome/Edge 能正常打开 YouTube。只有错误明确提示登录要求时才更新 cookies.txt；429 需要等待；403 请按检查器建议分别检查令牌、代理出口和视频权限。平台验证会变化，软件不能承诺永久绕过。

**Q2：保存 cookies 文件提示「缺少登录凭据」？**
导出时未处于登录态。确认 YouTube 右上角头像已登录后再导出，文件里应有 `SID` 和 `LOGIN_INFO`。

**Q3：首次转写很慢/卡住？**
首次使用会自动下载 Whisper 模型（约 500MB），需要联网，日志中有提示；下载完成后使用本地缓存。

**Q4：OCR 没有识别到文字？**
「仅画面字幕 OCR」需要系统安装 Tesseract OCR 和对应语言包。处理页会明确显示 OCR 是否真正成功；若回退到 Whisper，会显示原因和“实际字幕来源”，不会再静默切换。

**Q5：字幕和声音对不上？**
视频画面有烧录字幕时，处理流程会自动用画面字幕的帧级时间校正音频字幕的整体偏移（日志会记录校正量）；也可以在字幕页点「自动对齐」重新校正，或用「整体偏移」输入 ±秒手动微调，最后保存并重新渲染。

**Q5：任务中途关闭窗口？**
关闭窗口会弹确认（防止误关中断任务）。若仍发生异常退出，可用「复制调试信息」把日志发给维护者。

**Q6：下载 YouTube 时闪黑色窗口？**
已修复：外部程序（ffmpeg/node）以无窗口方式静默运行。

**Q7：渲染出来的字幕位置/大小不对？**
字号与位置按视频分辨率自动适配（1080p 下 24 号 ≈ 48px）；可在「处理页→高级→字幕底部位置/渲染质量」调整，改后重新渲染。

**Q8：批量处理中途失败了怎么办？**
失败的条目不影响其他条目。修好原因（如网络、Cookies）后点该条的「续跑」，会从中断的阶段继续。程序关闭后再打开，队列会自动恢复。

**Q9：配音开关是灰色的？**
VoxCPM2 没装好或路径不对，开关下方会写明原因。按 `docs/配音安装说明.md` 检查 python.exe 路径和模型目录；如果是程序运行中装好的，请重启程序。

**Q10：如何找回之前的任务？**
「文件页 → 任务历史」可查看历史任务并打开输出；任务数据在用户目录 `AppData\Roaming\YouTubeBiliLocalizer\`。
