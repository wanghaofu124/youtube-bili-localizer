# YouTube 下载可靠性 v0.2.3

## 对外说明

YouTube Bili Localizer 现在能够在 YouTube 要求额外浏览器验证时，按需启动本机 Chrome/Edge 获取当次媒体请求所需的 PO Token。普通 URL 下载不再无条件重复解析两次；失败时会区分浏览器验证、登录 Cookies、请求频率、浏览器缺失和一般 403，给出对应处理建议。

## 用户问题与证据

- 公开可观看的视频在应用中返回 `Sign in to confirm you're not a bot` 或 HTTP 403。
- 旧错误文案把所有 403 都归因于网络 IP 或 Cookies，用户无法判断真正缺少的是媒体令牌、登录状态还是浏览器组件。
- 普通下载先 `download=False`、再 `download=True`，增加一次完整解析和被限流机会。
- 代理只靠外部环境配置，元数据、视频、封面与验证浏览器可能不走同一出口。

## 本次目标

1. 默认使用可关闭的自动浏览器验证，发行包内置 `yt-dlp-getpot-wpc`。
2. 普通下载只执行一次 yt-dlp 提取；只有用户主动要求 CC `reuse allowed` 预检时执行两次。
3. 元数据、视频、封面和 PO Token 验证使用同一任务代理。
4. 错误至少分类为：验证组件缺失、验证失败、浏览器缺失、登录要求、429、一般 403。
5. 代理凭据不写入任务历史、公开任务快照或调试日志。

## 非目标与边界

- 不保证 YouTube 永久可下载；平台可以随时改变验证方式。
- 不提供代理池、账号轮换、验证码绕过或风控规避。
- 自动浏览器验证不代替账号登录；年龄限制、会员或私有视频仍需用户自己的有效 Cookies 和访问权限。
- 本次不增加批处理、失败重试或断点续传。

## 成功指标

- 技术验收：mock 测试证明普通任务单次提取、CC 任务保留预检、验证开关和代理传递正确、敏感代理不持久化。
- 交付验收：onedir EXE 内可发现 PO Token Provider；依赖中心显示组件已包含；关闭验证后不探测或启动浏览器。
- 体验基线：从 v0.2.3 开始记录真实公开授权样例的成功/失败分类。发布前不虚构成功率；积累至少 10 个样例、2 个网络环境后再设定成功率目标。

## 验收场景

1. 自动验证开启且组件完整：yt-dlp 使用 `mweb` 和 provider 的 `fetch_pot=auto`。
2. 自动验证关闭：不探测、不启动浏览器，保留常规 yt-dlp 行为。
3. 一般公开 URL：只调用一次 `extract_info(download=True)`。
4. 勾选 `reuse allowed`：先读取许可证，通过后下载。
5. 代理含账号密码：可用于当次任务，但任务 API、历史数据库和复制调试信息不出现原值。
6. 403：不再断言“一定是 IP 或 Cookies”，显示可操作的分层建议。
