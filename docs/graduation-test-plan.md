# 毕业设计测试方案（语音识别与翻译方向）

## 1. 课题定位

建议题目：**《面向视频本地化的语音识别与字幕翻译质量评估及流程优化》**。

课题聚焦英文视频生成中文字幕时最影响成片质量的两个环节：语音识别（ASR）的错词、漏词，以及机器翻译的错译、漏译和术语不一致。字幕分句与渲染使用当前稳定版本，作为固定条件和基本质量检查，不作为本次研究的主要变量。

论文研究的是现有模型与处理流程在特定材料上的效果，不宣称训练了新的 ASR 或翻译模型，也不把少量样本的结果推广到所有语言和视频。

## 2. 研究问题

- **RQ1：** 在相同音频和设备上，项目当前支持的 ASR 配置在识别准确率与处理耗时之间有什么差异？常见错词、漏词集中在哪些语音条件？
- **RQ2：** 固定正确源文后，不同翻译配置的忠实度、完整度、术语一致性和中文自然度有什么差异？
- **RQ3：** ASR 错误会怎样传递到译文？对 ASR 文本做校正后，字幕质量的改善是否值得增加的时间和资源？

## 3. 当前线索与试运行

已有任务日志显示，单条字幕可能受到专有名词误识、漏词、口语重复和人声漏检影响；用户也反馈过 10 分钟视频的翻译阶段超过 20 分钟。2026-10-02 的一次任务中，翻译阶段记录为 16 分 24 秒。这些是确定研究问题和性能记录方式的线索，**不是可直接比较的实验结果**：任务长度、模型、硬件和设置必须统一后才能得出结论。

## 4. 数据集与人工参考

先准备 **6 段左右、每段 2–3 分钟**的英文视频片段，总时长约 12–18 分钟。覆盖单人讲述、多人对话、快语速、口音或背景噪声、专有名词较多等情况。优先使用已有任务的本地音频，避免重复下载。

每段建立一份人工校正的英文参考转写：

1. 对照音频逐句校正，保留实际说出的内容；不确定处标为不确定，不凭上下文补造词语。
2. 统一大小写、缩写和标点处理规则；计算词错误率时忽略大小写和标点。
3. 至少 20% 由第二位标注者独立复核；统计一致率，并对分歧项复核。
4. 对人声漏检、数字、否定词、专有名词和说话人变化单独做错误标签。

测试范围先限定为**英文语音到中文字幕**。如果需要验证俄语或其他小语种，应另建同语言参考集并单独报告，不能与英文样本混算。

## 5. 对照实验

### 5.1 ASR 准确率与耗时

- 以当前实际使用的 `large-v3` 为主配置；可与项目已支持的 `medium` 做一次受控比较，评估速度与准确率的取舍。
- 每个配置使用完全相同的音频、语言、硬件、解码设置和词级时间戳选项。记录模型加载/预热时间与正式转写时间，避免混在一起。
- 将各配置输出与人工参考转写对齐，统计 WER、CER，以及专有名词、数字、否定词、漏句等错误类型。
- 不把不同视频、不同硬件或不同设置下的任务日志当作模型 A/B 结果。

### 5.2 翻译模型质量

- 从全部片段中分层抽取 **60–100 个语义单元**，包含普通口语、代词指代、否定、数字、专有名词和 ASR 易错句。
- 给每个候选翻译模型提供同一份**人工校正源文**，这样比较反映翻译差异，而不是 ASR 输入差异。
- 先比较当前常用翻译配置和一个候选配置；使用盲评编号，不向评审者显示模型名称。
- 两名评审按 1–5 分评价忠实度、完整度、术语一致性和中文自然度，同时记录错译、漏译、增译、术语错误及严重程度。模型不得评价自己的译文。

### 5.3 ASR 错误对翻译的影响

另选 **30–50 条**含 ASR 错误或易错点的字幕，保持翻译模型和其他参数不变，比较三种输入：原始 ASR、人工校正后的 ASR、人工参考源文。评审译文差异，并记录人工校正每条所需时间。该小样本实验用于量化错误传播及校正收益，不要求重新跑整段视频的所有模型。

### 5.4 端到端验证

选一段约 2–3 分钟的片段走完现有流程，检查识别、翻译、时间对齐、字幕编辑和成片。分句规则保持固定；时间轴重叠、漏字幕和渲染失败作为系统质量检查项，不与 ASR/翻译准确率混为一项。

## 6. 指标

| 环节 | 指标 | 统计方式 |
| --- | --- | --- |
| ASR | WER | `(替换数 + 删除数 + 插入数) / 参考词数`；大小写与标点归一化后对齐 |
| ASR | CER | 字符级错误率；作为专有名词、拼写变化较多时的补充指标 |
| ASR | 关键错误 | 分别统计数字、否定词、专有名词、整句漏检和说话人变化错误 |
| ASR | 速度与资源 | 转写秒数/音频秒数、模型、设备、CPU/GPU、内存；预热单独记录 |
| 翻译 | 人工评分 | 忠实度、完整度、术语一致性、自然度各 1–5 分；报告均值和分布 |
| 翻译 | 错误计数 | 按错译、漏译、增译、术语错误分类，并记录严重程度与受影响条数 |
| 错误传播 | 输入条件差异 | 比较原始 ASR、校正 ASR、人工参考源文下的翻译评分和严重错误数 |
| 效率 | 时间与费用 | 记录音频长度、调用次数、阶段耗时、API 费用或本地运行时间 |
| 系统检查 | 时间轴与渲染 | 检查字幕重叠、漏字幕、布局溢出和成片可播放性；作为辅助结果单列 |

WER/CER 不能直接代表字幕可读性；翻译评分也不能替代 ASR 准确率。论文分别报告各环节结果，并展示少量典型错误案例。

## 7. 低成本执行顺序

1. **小规模试跑：** 先选 2 段各约 2 分钟的音频，人工校正参考文本；确认标注耗时、ASR 对齐方法和实际模型运行时间。
2. **ASR 对照：** 在这 2 段上跑 `large-v3` 与 `medium`。如果耗时或电脑负载不适合，再固定只测 `large-v3` 与人工参考的误差，不扩大模型范围。
3. **翻译盲评：** 先评 20 条，确认评审标准清楚后再扩到 60–100 条。源文统一使用人工校正版本。
4. **错误传播：** 只对 30–50 条代表性样本比较三种源文输入，不重复翻译整片。
5. **端到端：** 最后只跑一段短片验证系统集成，保留每阶段耗时和设备负载。
6. 汇总每个片段及总体结果；报告均值/中位数、评审分歧和不确定范围，不只挑成功案例。

## 8. 固定条件与记录要求

每轮至少记录：代码版本、操作系统、CPU/GPU/内存、视频匿名编号和时长、ASR 模型与参数、翻译模型与参数、源文类型、字幕分句版本、调用次数、各阶段耗时、错误/异常和评审编号。ASR 对照中保持音频和设备不变；翻译对照中保持源文不变。

先复用已下载的本地音频和字幕产物。模型第一次加载、模型下载、网络等待和正式推理分开记时；本地模型的耗时和云 API 的耗时/费用分开报告。每次只改变一个主要变量。

## 9. 论文结论边界

结论限定在本次英文到中文样本、所选模型、硬件和测试设置内。可以说明某个配置在本数据集上的错误率、耗时和错误类型；不能据此宣称某模型对所有口音、小语种或题材都最好。公开视频内容仅在授权范围内用于论文附件和演示。
