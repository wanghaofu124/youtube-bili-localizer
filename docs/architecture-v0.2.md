# v0.2 架构边界

工作台采用模块化单体。依赖方向固定为：桌面壳/HTTP/CLI/Tk 适配器 → 应用服务与配置 → 流水线领域逻辑 → yt-dlp、Whisper、FFmpeg、Playwright 等基础设施。

## 决策

- React 工作台是唯一新增功能的 UI；Tk GUI 只维护启动与核心兼容性。
- `workbench_config.py` 是工作台默认值、归一化和预检规则的唯一来源。`dependencies.py` 是宿主依赖发现与安装的唯一入口；前端和预检共享它的能力快照，媒体流水线只通过解析后的命令或模型路径使用依赖。
- 依赖安装串行执行并要求用户明确确认。HTTP 层只接受白名单组件 ID，不能传入任意命令、下载地址或安装路径；安装失败保留有限日志并允许重试。
- 修改型本地 API 使用每次启动随机 CSRF token，并校验 Host、Origin 与 Content-Type；远程网页即使扫描到随机端口也不能触发安装、删除或发布操作。
- 外部依赖安装进程属于对应安装任务：用户取消或工作台退出时终止整个子进程树。Whisper 模型下载在进程内执行，取消会在当前网络请求结束后生效。
- 默认字幕来源为音频。OCR 一次抽取全帧，逐帧优先上次成功区域，低置信度时扩大到其他区域；临时 JPEG 帧在成功、失败和取消后统一清理。纯 OCR/合并模式在下载前检查 Tesseract 及所选语言包，运行结果明确记录实际使用 OCR 还是回退 Whisper。
- `PipelineContext` 为每个任务持有独立取消令牌和结构化事件回调。维护期 Tk 入口的旧全局取消函数只是兼容适配器，不参与工作台任务。
- SQLite 与任务目录内原子写入的 `job_manifest.json` 同步保存工作流状态；输出目录扫描只描述当前磁盘占用。启动时只把遗留任务的当前运行阶段迁移为 `interrupted`，此前检查点会逐个验证。
- 演示入口只读取仓库内预生成的授权成片与字幕，不加载模型、不请求 API；真实任务先创建草稿，再在任何 URL 下载前执行动态准备检查。

## 分阶段工作流

- `workflow.py` 是阶段业务逻辑的唯一实现，提供 `acquire / extract / translate / render / publish`。CLI 的 `run_pipeline()` 只是顺序调用这些阶段；桌面服务调用同一函数，不保留第二套流水线。
- 每阶段只消费上游检查点，并只替换自己拥有的产物。视频、音频和成片用 ffprobe 验证，字幕 JSON 验证结构和时间范围，SRT 验证有效时间段。
- 工作台同一时间只运行一个耗资源阶段。`run-all` 只是调度尚未完成的真实阶段并在第一个错误处停止；取消只作用于当前 `PipelineContext`。
- Whisper 转写只接收应用管理目录中的完整本地模型路径。缺失模型由准备检查阻塞，不能把模型名称传给 faster-whisper 触发隐式下载。
- 配置更新按最早受影响阶段向下游标记 `stale`：素材与下载参数从获取阶段失效；字幕来源和推理参数从提取阶段失效；翻译参数从翻译阶段失效；样式和编码参数从渲染阶段失效；发布文案只影响发布阶段。

工作台接口：

- `POST /api/jobs` 只创建草稿。
- `POST /api/jobs/{id}/prepare` 生成准备清单。
- `PATCH /api/jobs/{id}/options` 保存配置并返回失效阶段。
- `POST /api/jobs/{id}/stages/{stage}/run` 运行单阶段。
- `POST /api/jobs/{id}/run-all` 从下一有效阶段连续运行到渲染。
- `POST /api/jobs/{id}/resume` 验证检查点后继续中断阶段。

## 稳定边界

- B 站自动化停在人工提交前。
- API 不回传 Key、Cookies 内容或任意未登记路径。
- 用户 `.env`、SQLite、输出目录和浏览器 Profile 位于 `%APPDATA%\YouTubeBiliLocalizer`，升级不会覆盖。
- 应用管理的 Whisper 模型、Playwright 浏览器与工具目录也位于同一用户数据根目录；新安装组件在当前进程内重新发现，不要求重启工作台。WebView2 因窗口启动前即需要，由桌面壳负责前置检测。
- v0.2 不承诺批处理、缓存、下载重试或自动投稿。
